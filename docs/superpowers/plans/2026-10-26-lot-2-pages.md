# Lot 2 — Pages et documents : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (native) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Édition de la structure des documents (pivoter, supprimer, réordonner, insérer, extraire, fusionner, scinder) avec annuler/rétablir, enregistrement atomique et indicateur de modification, dans l'application et en ligne de commande.

**Architecture:** `mega-core::edit` (commandes + historique memento) et opérations de pages sur `Document` ; l'acteur applique les commandes, invalide son cache et renvoie l'état d'édition ; backend et frontend n'ajoutent que des commandes miroirs, la sélection de vignettes, le glisser-déposer et les dialogues.

**Tech Stack:** inchangée (pdfium-render : `set_rotation`, `delete`, `create_page_at_index`, `copy_page_range_from_document`, `create_new_pdf`, `save_to_bytes`).

**Spec:** `docs/superpowers/specs/2026-10-26-lot-2-pages.md`

## Global Constraints

Celles des Lots 0 et 1 (SPDX, langues, lints anti-panique ADR-0005, frontières, `strings.ts`,
docs `///`, `[Apprentissage]`), plus : **aucune écriture sur disque sans passer par
`Document::save/save_as` ou les fonctions `merge/split` (atomiques)** ; le fichier d'origine
n'est jamais tronqué avant que le remplaçant soit complet.

## Review Focus

1. Échec d'écriture (dossier inexistant, chemin = dossier, disque plein simulé) : l'original
   reste intact et lisible (`save_as_failure_leaves_original_intact`).
2. Suppression de toutes les pages : refusée avec `InvalidOperation` (`delete_all_pages_is_refused`).
3. Annuler après enregistrement : possible ; `is_modified` redevient vrai (`undo_after_save_marks_modified`).
4. Historique borné : 25 éditions → 20 annulations max, mémoire bornée (`history_is_bounded`).
5. Édition pendant qu'un rendu est en cache : les images périmées ne sont plus servies
   (`apply_invalidates_render_cache`, service).
