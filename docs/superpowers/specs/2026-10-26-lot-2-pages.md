# Lot 2 — Pages et documents : spécification

Statut : approuvée par mandat (exécution autonome). Référence : conception §5 Lot 2, ADR-0006.

## Intention

Faire de MegaUltraPDF un **éditeur de structure** : réorganiser, pivoter, supprimer, insérer,
extraire, fusionner, scinder des pages, puis **enregistrer** sans jamais corrompre le fichier
d'origine, avec **annuler / rétablir** sur toute édition. C'est le lot qui introduit le patron
Command et l'écriture atomique ; toutes les éditions ultérieures (annotations, formulaires,
contenu) s'y brancheront.

## Périmètre (ce qui entre) — `docs/FONCTIONNALITES.md`, section « Pages et documents »

- Pivoter des pages (enregistré dans le fichier, par pas de 90°), supprimer, **réordonner par
  glisser-déposer des vignettes**, extraire vers un nouveau fichier, insérer une page vide
  (format de la page courante ou A4), insérer les pages d'un autre PDF, fusionner plusieurs
  fichiers (nouveau document), scinder (par plages, toutes les N pages, par signets de
  premier niveau).
- Sélection multiple de vignettes (clic, Ctrl+clic, Maj+clic) ; actions sur la sélection.
- Enregistrer (Ctrl+S) / Enregistrer sous (Ctrl+Maj+S) ; écriture atomique (fichier temporaire
  puis renommage) ; indicateur « modifié » sur l'onglet ; confirmation à la fermeture d'un
  onglet ou de la fenêtre si des modifications sont en attente.
- Annuler / Rétablir (Ctrl+Z / Ctrl+Y), avec libellé de l'action, historique borné.
- CLI : `mega merge`, `mega split`, `mega rotate`, `mega extract` (+ `info`, `render` existants).

## Hors périmètre

Annotations (Lot 3), formulaires (Lot 4), contenu (Lot 5), chiffrement et métadonnées
(Lot 6). La rotation **d'affichage** du Lot 1 reste distincte de la rotation **enregistrée**.

## Architecture ajoutée

- `mega-core::pagespec` : `PageSpec` (plages 1-based « 1-3,5,8- »), analyse et validation.
- `mega-core::edit` : `enum EditCommand` (sérialisable : `RotatePages`, `DeletePages`,
  `MovePages`, `InsertBlankPage`, `InsertPagesFromFile`), `trait Command { label, apply }`,
  `History` **par memento** (octets du document avant chaque commande, borné à 20 étapes et
  256 Mo), `Document::apply / undo / redo / can_undo / can_redo / is_modified / save / save_as`.
- `mega-core::Document` : opérations de pages (`rotate_pages`, `delete_pages`,
  `insert_blank_page`, `insert_pages_from`, `move_pages`, `extract_pages -> Vec<u8>`),
  fonctions libres `merge(paths) -> Vec<u8>` et `split(doc, parts) -> Vec<Vec<u8>>`.
- `mega-core::service` : requêtes `Apply`, `Undo`, `Redo`, `Save`, `SaveAs`, `ExtractPages`,
  `MergeFiles`, `SplitDocument` ; chaque édition **invalide le cache** du document et renvoie
  un `DocumentSummary` à jour plus un `EditState { modified, can_undo, can_redo, undo_label,
  redo_label }`.
- Backend : commandes miroirs ; `api.ts` ; frontend : état d'édition, sélection de vignettes,
  glisser-déposer HTML5 dans la barre latérale, dialogues insérer / fusionner / scinder /
  confirmation de fermeture, raccourcis.

## Décisions (mes choix, consignées)

1. **Undo par memento** (octets avant la commande) plutôt que par commandes inverses : simple,
   toujours exact, et les documents édités dans un lecteur de bureau tiennent en mémoire ;
   borné (20 étapes, 256 Mo). Le trait `Command` reste (`label`, `apply`) pour que les lots
   suivants ajoutent des commandes sans toucher à l'historique.
2. **Réordonner** = copier la page depuis une copie du document (chargée des mêmes octets) à
   la nouvelle position puis supprimer l'ancienne (pdfium-render n'expose pas `FPDF_MovePages`).
   Les signets qui visaient la page déplacée peuvent être perdus : documenté dans l'interface
   (« les signets peuvent être affectés ») et dans la note du lot ; `lopdf` (Lot 5) permettra
   mieux.
3. **Écriture atomique** : fichier temporaire dans le même dossier, `fs::rename` par-dessus
   (remplacement atomique sous Windows via `MoveFileEx`). Le document est chargé en mémoire :
   aucun descripteur ouvert sur l'original.
4. **Après enregistrement**, l'historique est conservé (on peut encore annuler) mais
   `is_modified` devient faux jusqu'à la prochaine édition.
5. Suppression de **toutes** les pages refusée (`CoreError::InvalidOperation`).
6. Fusion et scission produisent de **nouveaux documents** (ouverts dans de nouveaux onglets
   ou écrits sur disque selon le contexte) ; l'original n'est pas modifié.

## Concepts Rust travaillés

Traits et objets de trait (`Box<dyn Command>`), `enum` sérialisée avec `serde` (tag), memento
et `VecDeque` bornée, `std::fs::rename` et fichiers temporaires, `impl FromStr` pour `PageSpec`,
tests d'intégration CLI avec fichiers temporaires, erreurs métier (`InvalidOperation`).

## Checklist de validation (CDP)

1. Vignettes : Ctrl+clic sur 2 pages, « Pivoter » → vignettes tournées, onglet marqué « • ».
2. Glisser la vignette 3 avant la 1 → ordre 3,1,2 (texte « Page 3 » en premier).
3. Supprimer la page 2, Ctrl+Z → revient, Ctrl+Y → repart.
4. Insérer une page vide après la 1 → 4 pages ; insérer depuis `outlined.pdf` → 7 pages.
5. Ctrl+S sur une copie temporaire → fichier réécrit, « • » disparaît ; rouvrir : ordre conservé.
6. Fermer un onglet modifié → confirmation ; annuler garde l'onglet.
7. Fusionner simple.pdf + outlined.pdf → nouvel onglet 6 pages ; scinder toutes les 2 pages → 2 fichiers.
8. CLI : `merge`, `split --every 2`, `rotate --pages 1 --degrees 90`, `extract --pages 2-3`.
